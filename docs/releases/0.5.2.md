# gup `0.5.2`

> **TL;DR** — **gup says which Node it needs, and stops running as root.** On a Node older than 26.9, every command now stops at once with the version you have, where to get a newer one and the line that reinstalls gup — and npm installs the latest gup there instead of silently falling back to 0.3.2 or 0.2.2. gup refuses to run under `sudo`, as Homebrew does: on macOS a `sudo gup` left gup's folders to root, and every later run failed on them; the folder is now named with the command that gives it back, in the error and in `gup doctor`. A tool Homebrew installed is listed once, by `brew`. **If you ever ran `sudo gup`, run `gup doctor` once after upgrading.**

`npm i -g @charles_lindecker/gup@0.5.2 --allow-scripts=node-pty`

---

## 🟢 An older Node says so

gup needs Node 26.9: its interactive app loads OpenTUI's renderer through `node:ffi`, on by default from 26.9. Until now an older Node failed somewhere further on — the app said it needed 26.9, but `gup list` crashed inside a dependency. Every command now checks first, before any of the program loads, and stops with exit code 1:

```text
Error: gup needs Node.js 26.9.0 or newer — current version v24.11.0
Install a newer Node.js: https://nodejs.org/en/download
Then reinstall gup: npm install -g @charles_lindecker/gup@latest --allow-scripts=node-pty
```

`GUP_LANG=fr` gets it in French, with nodejs.org's French page.

The other half was npm's doing. Asked for a package without a version, npm installs the newest release whose `engines` accepts the running Node, and says nothing about the newer ones: with `engines` at 26.9, Node 22.13 to 26.8 kept getting gup 0.3.2, and Node 20 to 22.12 gup 0.2.2, at every `npm install -g`. `engines.node` is now `>=20`, the lowest any published gup declared, so npm always installs the latest gup — which then says which Node to install. The Node gup needs is still 26.9; a CI job installs the packed gup on Node 20 and checks that it stops with that message.

---

## 🔒 No more `sudo gup`

macOS's `sudo` keeps your home folder. A `sudo gup` therefore wrote gup's history, log, settings and update lock into **your** `~/Library/Application Support/gup`, as root — and every later run as you failed on them: `EACCES: permission denied, mkdir '…/gup/locks'`, no update started; on macOS and Linux a lock folder gup could not write even made the update wait forever for an "another gup" that did not exist.

- **gup refuses to run under `sudo`**, as Homebrew does. It never needed to: the packages that need administrator rights (MacPorts, Fink, pkgin, apt…) already run together behind the one `sudo` password gup asks for itself. Root's own runs — a root shell, a container — still go through.
- **The error names the folder and the fix**: `… belongs to root, not to you — gup was probably run with sudo. Give it back to your user: sudo chown -R <you> "$HOME/Library/Application Support/gup"`. The history's warning says the same.
- **`gup doctor` gains a File ownership line** on macOS and Linux: `gup's folders are yours`, or one warning per gup folder or file another user owns, each with its `chown`.
- An update lock gup may not write now ends the update with that error instead of waiting.

## 🍺 Homebrew tools listed once

A tool gup follows on its own — Starship, Terraform, the Symfony CLI… — but that Homebrew installed showed up twice: once under its own provider, once under `brew`. Both rows ran the same `brew upgrade`, so a formula brew could not install failed twice in one run, and a release the provider saw upstream before the formula packaged it came back after every update, a success that changed nothing. Once brew has scanned, the tool's own row now gives way to brew's.

The rows of the 51 providers that hand their update to a package manager also name it: `installedBy` (`brew`, `scoop`, `choco`, `winget`, `apt`, `dnf`) in `gup list --json`.

## ⬆️ Upgrade

```bash
npm i -g @charles_lindecker/gup@0.5.2 --allow-scripts=node-pty
gup --version     # 0.5.2
gup doctor        # File ownership: are gup's folders yours?
```

- **Drop-in** on Node 26.9 or newer: same commands, flags, settings file, schedules, history.
- **On an older Node**, npm now installs 0.5.2 and gup stops with the message above: upgrade Node (a version manager — fnm, nvm, Volta — keeps it from fighting your other projects), then reinstall gup.
- **`sudo gup` no longer runs.** Run `gup` without `sudo`; it asks for your password itself when a package needs it. If you ran it with `sudo` before, run the `chown` that `gup doctor` gives, once.
