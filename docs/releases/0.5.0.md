# gup `0.5.0`

> **TL;DR** — **Updates run inside the app, and gup remembers what it did.** An update confirmed in the interactive app now runs in a live terminal pane embedded in it — progress bars, prompts you can answer, one UAC or `sudo` prompt for every administrator package — and packages are picked by checking them. gup keeps a debug log and reads its activity history back as a **Journal** view, `gup report` and a self-contained **HTML report**; chosen packages can be **updated on a schedule**; **ten themes** hold every text to WCAG AA; providers of another OS are greyed out and never probed. **0.4.0 was never published**, so this is also the release that ships its full-screen OpenTUI interface and its **Node ≥ 26.9** floor. Coming from 0.3.2: upgrade Node first.

`npm i -g @charles_lindecker/gup@0.5.0 --allow-scripts=node-pty`

## 📦 Coming from 0.3.2: 0.4.0 is in here too

0.4.0 was prepared, committed and documented, but never tagged nor published to npm. Everything in its [release notes](0.4.0.md) reaches users for the first time with 0.5.0:

- **The full-screen OpenTUI app** in place of `@inquirer/prompts` and `ora`: title bar, sidebar, bordered panels, dialogs, key-hint bar, mouse support. Piped or redirected, nothing is drawn and OpenTUI is never loaded.
- **No more frozen terminal on Windows**: PATH lookups resolve in-process (a 3.3–3.8 s synchronous burst down to 9 ms), probes run 8 at a time, every probe and scan is bounded in time with stdin closed.
- **Node ≥ 26.9.0**, for OpenTUI's native renderer loaded through `node:ffi` — see Upgrade below.
- `adm-zip` 0.6.1, `brace-expansion` 5.0.12 and `nanoid` 3.3.18 for their advisories.

## 🖥️ Updates inside the app

Confirm an update in **Paquets** and it no longer leaves the screen: a run view lists every package (state, provider, versions, duration, admin and retry tags) above a terminal pane showing the install in progress, colours and progress bars included.

- **You stay in control.** `s` skips the install in flight, `x` stops everything after a confirmation, `v` enlarges the pane. `t` (or a click on the pane) hands the keyboard to the installer — a licence, a `[Y/n]`, a password — until `Ctrl+G`; gup never answers for you.
- **Administrator packages in one go**: one UAC window on Windows, one `sudo` password typed in the pane on macOS and Linux, for the whole batch — in the menu as in `gup update`. Recoverable failures offer their retry strategies in a dialog.
- **A stopped install is really stopped**: its whole process tree is gone before gup reports it, and an npm global package killed mid-download gets its previous copy back (`— version précédente restaurée`).
- **Multi-select that does what it says.** `Space` checks a package (or a whole provider from its row), `a` checks everything, a selection bar counts what is checked; `Entrée` updates the checked packages and nothing else — with nothing checked it says how to check instead of updating the row under the cursor.
- The embedded terminal is the optional `node-pty`. When it is missing or unusable, the confirmation says why and the update runs in your terminal, outside the app, as before. `GUP_PTY=off` turns it off; `gup doctor` reports its state.

## 📒 A history you can read

0.3.1 started recording every scan and update attempt, and never read it back. 0.5.0 reads it — for display only, never to make a decision.

- **Journal** view in the menu: an activity calendar, per-package update rhythm, every event with filters, and the newest debug-log lines.
- **`gup report`** writes a one-file, offline **HTML report** (overview, calendar, packages, failures, sessions; light and dark themes, printable, a data table behind every chart) and opens it in your browser; `--format text|json|csv` writes to stdout for scripts.
- **Debug log** of every run, one JSON line per event, kept 14 days: `--log-level` / `GUP_LOG_LEVEL`, `gup log` to read it, `gup log export` for a diagnostic `.zip` to attach to a bug report — redacted, nothing uploaded.
- Secrets are masked before they reach the debug log, the history or an export (tokens, keys, credentials in URLs, secret-named settings), and the log and exports shorten the home directory to `~`.

## ⏰ Scheduled updates

`gup schedule add npm-g:typescript --every weekly` — or `p` on the checked packages in **Paquets** — updates chosen packages daily, weekly, monthly or on a cron expression. Schedules name packages, never a whole provider. There is no daemon: the OS starts a short-lived `gup` every 15 minutes (a per-user Task Scheduler task, a launchd agent or a crontab block), registered only while a schedule is enabled (from the menu, only once you have agreed to it). Scheduled runs never elevate, never force and never prompt. The **Planification** view shows each schedule's next and last run.

## 🎨 Readable everywhere

- **Ten themes** — `terminal` (default), `auto`, `dark`, `light`, `high-contrast`, `colorblind`, `dracula`, `catppuccin-mocha`, `github-light`, `monochrome` — with a live preview and a colour editor.
- Every text reaches **WCAG AA** (4.5:1; 7:1 with the AAA setting) and every border 3:1, custom colours included: an unreadable colour is moved to the closest readable one. The default theme reads the terminal's palette when it answers, and picks safe slots on the Windows console, which never does.
- Only symbols that Consolas and Cascadia Mono both have, so nothing turns into a boxed question mark in the Windows console, ASCII when the terminal needs it, `NO_COLOR` honoured, layouts checked at 80 columns.
- The **Options** view edits everything in place, saved at once in `config.json`.

## 🧭 Providers know their OS

The 35 providers tied to an operating system declare it: elsewhere they are never probed, scanned nor updated, and the **Providers** view lists them greyed out. Of the 153 registered providers, 139 run on Windows, 132 on macOS and 126 on Linux. A `winget` shim on a Linux `PATH` no longer lights up winget, and `gup update brew-cask:x` on Windows exits 2 with a message saying where it runs.

## 🔒 Security

- On Windows a bare command name is looked up on the `PATH` only, never in the working directory: a planted `npm.cmd` in the folder gup starts from is not run.
- The elevated batch re-checks every target before running it as administrator, receives its paths whole even with spaces, and never writes into your log directory.
- gup opens only `.html` / `.htm` files with the default application: `gup report --out x.hta` is written but not opened.
- The HTML report runs only its own script (hash-based CSP, Trusted Types) and shows history text as text; installer output is drawn inside the pane, so its escape sequences cannot drive your terminal.
- `npm audit`: **0 vulnerabilities**.

## ⬆️ Upgrade

```bash
node --version   # must be >= 26.9.0
npm i -g @charles_lindecker/gup@0.5.0 --allow-scripts=node-pty
gup --version    # 0.5.0
gup doctor       # "Terminal intégré" says whether updates run inside the app
```

- **Breaking — Node ≥ 26.9.0** (0.3.2 needed 22.13). npm reports `EBADENGINE` on older lines.
- **npm 11 asks before running install scripts.** node-pty has some (they fetch or build its native part). `--allow-scripts=node-pty` runs them without a warning; a plain `npm i -g @charles_lindecker/gup` runs them with a warning; with `strict-allow-scripts=true` the install fails until you add the flag. To trust node-pty once for all global installs: `npm config set allow-scripts=node-pty --location=user`.
- **node-pty is optional.** Windows and macOS get a prebuilt binary. On Linux it is compiled at install time and needs Python 3 and a C/C++ toolchain (`build-essential`, `gcc-c++ make`, `base-devel`); without them — or with `--ignore-scripts` — npm skips it, gup installs and works, and updates started from the app run in your terminal instead of the pane.
- Every command and flag of 0.3.2 is still there with the same meaning; `log`, `report` and `schedule` are new. The interactive mode is a different program: the full-screen app.

## ⚠️ Known issues

- On a light terminal (Terminal.app's Basic profile), the run view's pane draws an installer's default-coloured output in white, hard to read. Tracked as an expected failure in the contrast audit ([themes guide](../guide/themes-and-accessibility.md#the-embedded-terminal)).
- `gup update provider:package` updates without scanning first, so its history record has no `from` / `to` versions; the menu's records do.
- The landing site's translations were back-translated and checked, not yet reviewed by native speakers.
