# gup `0.2.2`

> **Reconstructed on 2026-08-22.** `0.2.2` was published to npm on 2026-07-03 but was never tagged and never got a GitHub Release or release notes. This file is rebuilt from the two commits between `0.2.1` and the version bump ([`607580c`](https://github.com/LINDECKER-Charles/gup/commit/607580c), [`029e2a0`](https://github.com/LINDECKER-Charles/gup/commit/029e2a0)); it was not written at release time.

> **TL;DR** — One provider removed, nothing else. `docker-images` is gone from the registry (131 → 130 providers): local images are workload artifacts, not tools to keep up to date. No flag, command, or output shape changed.

`npm i -g @charles_lindecker/gup@0.2.2`

## 🗑️ `docker-images` provider removed

The provider listed every locally tagged image and offered to `docker pull` it. `0.2.0` had already stopped it from failing on images built locally (the `RepoDigests` probe), but the remaining behaviour was still wrong in kind: the images on a machine belong to the projects and workloads that run there, and refreshing them is a deployment decision, not machine maintenance. That is the line [`scope.md`](../guide/scope.md) draws — `gup` updates *tools*, and an image is not one.

Removed:

- `src/providers/containers/docker-images.ts` and its registration in `src/core/registry.ts`
- `tests/providers/containers.test.ts` — the `docker-images` cases (180 lines)
- its entry in the landing-page provider list (`index/src/data/providers.js`)

`docker-desktop`, `podman-desktop`, `rancher-desktop`, `nerdctl`, `oras` and `dive` are unchanged.

Documentation updated in the same commit: `docs/how-gup-works.md` and `docs/providers-catalog.md` (today under [`docs/development/`](../development/how-gup-works.md) and [`docs/guide/`](../guide/providers-catalog.md)).

## ⬆️ Upgrade

```bash
npm i -g @charles_lindecker/gup@0.2.2
gup --version  # 0.2.2
```

Drop-in. A script that targeted `docker-images:<image>` explicitly, or filtered with `--provider docker-images`, now gets the standard unknown-provider error; nothing else is affected. Engines unchanged (`node >= 20`).
