# gup `0.2.0`

> **TL;DR** — Une seule prompt UAC pour tous les paquets Chocolatey, un Ctrl+C qui débloque enfin les installs gelées, et l'arrêt définitif des conflits entre Chocolatey/winget et tes toolchain managers (nvm, fnm, pyenv, asdf, volta, mise…).

`npm i -g @charles_lindecker/gup@0.2.0`

---

## ✨ Nouveautés

### 🔐 Batch UAC unique pour les paquets admin (`feat/elevation`)

Avant : `gup update --all` te jetait 21 lignes `SKIP — relancer gup en admin` pour Chocolatey, et tu devais relancer toute la commande en admin.

Maintenant : les paquets `requiresAdmin` sont détectés au scan, séparés, et dispatchés ensemble derrière **une seule prompt UAC**.

```
21 paquet(s) nécessitent les droits administrateur. Ouvrir une invite UAC ? (O/n)
```

- Round-trip JSON via fichier tmp randomisé, child élevé spawné par `Start-Process -Verb RunAs -Wait` (Windows) / `sudo` (POSIX)
- Sous-commande masquée `__admin-batch <file>` câblée dans le CLI (jamais documentée, jamais auto-discoverable)
- Refus de l'UAC = SKIPPED (choix délibéré), pas FAILED
- `--yes` saute la prompt

### ⏱️ Timeout + Ctrl+C pour débloquer les installs gelées (`feat/skip`)

MSI mutex, download stallé, installer qui ignore `--silent` et bloque sur une fenêtre invisible : ces wedges ne gèlent plus tout le run.

- **Per-install wall-clock timeout** (défaut 1200s), override via `--timeout`, `GUP_INSTALL_TIMEOUT`, ou le menu Options
- **Ctrl+C** = skip le paquet courant, le batch continue
- **Ctrl+C × 2** = stop le batch propre
- Tree-kill sur Windows pour vraiment tuer les sous-process orphelins
- Dispatch unitaire (plus de `updateAll` opaque) → le skip mappe sur 1 paquet précis

### 🧬 Filtre d'ownership polyglotte (`feat/ownership`)

Si tu installes Node.js via `nvm-windows` mais que Chocolatey a aussi un `nodejs` outdated dans son catalogue, l'upgrade Chocolatey shadow ton shim et **casse tes scripts versionnés au prochain shell**. Pareil pour python/ruby/go/rustc/docker/git.

Désormais, `gup` :
1. Résout le binaire sur le `PATH`
2. Infère son owner réel (winget, scoop, choco, **nvm**, **nvm-windows**, **fnm**, **volta**, **mise**, **pyenv-win**, **asdf**, **proto**, **uv**…)
3. Si l'owner ≠ le provider qui propose l'update, le paquet est masqué silencieusement

Si le binaire n'est pas sur `PATH` → on garde le paquet (pas de fausse exclusion).

## 🐛 Fixes

### `fix(choco)` — Exit codes `3010` / `1641` enfin reconnus comme succès

`vcredist140`, .NET runtimes, drivers, anything-SxS : Chocolatey forward le exit code MSI, qui est `3010` = "succès, reboot requis". Avant : remonté en FAIL. Maintenant : OK avec advisory `redémarrage requis pour finaliser`, dédupliquée par batch.

### `fix(cli/install)` — `npm install -g github:LINDECKER-Charles/gup` fonctionne enfin

`dist/` est gitignored mais `bin: ./dist/cli.js` est dans `package.json` → install global git-based aboutissait à un shim cassé. Ajout de `prepare: npm run build` : npm exécute le build automatiquement à l'install ET à la publish (tarball npm ne change pas).

### `fix(cli/update)` — `gup update chocolatey` te dit quoi faire

Avant : `Format invalide: "chocolatey". Attendu provider:packageId` + exit 2. Opaque.

Maintenant :

```
Format invalide: "chocolatey". Attendu provider:packageId
"chocolatey" est un nom de provider, pas un identifiant de paquet
Essaye :
  gup list --provider choco
  gup update --provider choco --all
  gup           # menu interactif
```

Résolution case-insensitive sur id ET display name, suggestions canoniques uniquement (`choco`, pas `Chocolatey`). Aucun bare token n'est jamais escalé en mass-update silencieux.

### `fix(docker-images)` — Plus de FAIL sur les images locales

`DockerImagesProvider.listOutdated()` remontait toutes les images taggées localement (`docker build -t app .`) comme candidates au refresh → `docker pull` garanti FAIL → pollution du summary.

Une sonde `docker image inspect --format '{{json .RepoDigests}}'` filtre maintenant les builds locaux (RepoDigests vide) des images réellement pullables.

## 🛡️ Sécurité & hardening CodeQL

PR #22 a sorti 6 alertes GitHub Advanced Security, toutes fermées :

- **TOCTOU sur tmp files (5 alertes)** : `mkdtemp` pour parent dir (mode 0700 POSIX, ACL-restricted Windows) + flag `wx` (exclusive create) sur tous les `writeFile` en prod ET dans les tests
- **Shell command injection from env (1 alerte)** : suppression de la concaténation de ligne PowerShell, remplacée par un wrapper `.ps1` statique qui reçoit `node`, `cli`, `inputFile` comme paramètres positionnels via argv. Aucun chemin dérivé d'env ne touche un shell.
- **Refactor `regex.exec`** pour que CodeQL reconnaisse les sanitisers (`8c58c30`)
- **Validation stricte** du payload IPC du child élevé : rejet de length mismatch et d'outcomes malformés, fallback en per-target failure pour préserver le mapping des index (`f99579e`)

`npm run security` (audit-ci + ESLint security + tests sécurité) reste vert.
