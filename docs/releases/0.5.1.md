# gup `0.5.1`

> **TL;DR** — **gup speaks English, and French on demand.** Every word of the command line, the full-screen app, the HTML report and the 153 providers' messages now exists in English and in French; English is the default, and `gup language fr` switches for good. On Windows, gup no longer tries to update itself while it runs — the update that left the package half-replaced — but shows the command to run once it has exited. A real run's debug log also turned up updates that reported a success and changed nothing, or broke something: pip, composer, pnpm and winget are fixed. **French users: run `gup language fr` once after upgrading.**

`npm i -g @charles_lindecker/gup@0.5.1 --allow-scripts=node-pty`

---

## 🌐 English or French

- **English by default.** gup used to speak French only. It now chooses its language at startup: the `GUP_LANG` variable (`en`, `fr`, `fr_FR.UTF-8`…), then the `interface.language` setting, then English. The machine's own locale is not consulted; a `GUP_LANG` gup does not speak is ignored and reported, never fatal.
- **`gup language`** says which language gup speaks and why; **`gup language fr`** saves French and confirms in it. To install in French in one line — `&&` works in cmd, bash, zsh, fish and PowerShell 7; in Windows PowerShell 5.1, run the two commands one after the other:

  ```bash
  npm install -g @charles_lindecker/gup --allow-scripts=node-pty && gup language fr
  ```

  npm itself cannot carry the choice: npm 12 rejects unknown flags (`EUNKNOWNCONFIG`) and blocks a global package's own install scripts.
- **Options → Behavior → Language** changes it from the app; it applies at the next start. `gup doctor` reports it.
- **Everything is translated**: commander's help and usage errors (in commander's own English, behind `Error:`), every command's output, the app's views, dialogs and key hints (`y yes · n no`; `y`, `o` and `n` all answer), the HTML report (`<html lang>`, labels, `en-US` numbers and dates), the 153 providers' install hints and messages, settings issues, scheduler messages. Dates read `2026-10-03` and `Oct 03 14:22` in English.
- **Inputs accept both languages**: day names (`--on mon` or `--on lun`), confirmations. Command names, flags, provider and package ids, `--json` and CSV/JSON exports are unchanged — they were never translated.
- The elevated child (UAC / `sudo`) and the embedded terminal's trampoline speak their parent's language.

## 🪟 gup updating gup on Windows

A running gup keeps its native modules loaded — OpenTUI's renderer, node-pty's ConPTY — and Windows replaces no loaded DLL: `npm install -g @charles_lindecker/gup` started from gup failed half way and could leave the package emptied, its command gone. On Windows, gup's own row in **Packages** is now listed without a checkbox; Space says to quit gup and which command to run, the app prints that command when you quit, and `gup update`, `gup update --all` and `gup list` do the same:

```bash
npm install -g @charles_lindecker/gup@latest --allow-scripts=node-pty
```

macOS and Linux update gup like any other global package.

## 🔧 Updates that did not do what they said

Found in the debug log of a real run:

- **pip** upgraded a package that another installed package pins (semgrep pins `click~=8.4.2`, pydantic pins `pydantic-core`) and reported a success — leaving a broken environment until a later upgrade put the old versions back. gup now runs `pip check` before and after, puts the previous version back, and says which package and which requirement: `click 8.5.0 would break semgrep 1.178.0 (click~=8.4.2): back to 8.4.2`.
- **composer** global updates leave a package's dependencies locked, so an update that needed a newer one did nothing and exited 0: now `--with-dependencies`.
- **pnpm**: the `pnpm` row of pnpm's globals updates through `pnpm self-update` (pnpm refuses `pnpm add -g pnpm`); a self-update that leaves the pnpm on your PATH at its old version — pnpm 11+ installs into `$PNPM_HOME/bin` — is reported as such, with the folder to add to PATH.
- **winget**: when winget says no strategy can work — an upgrade the manifest forbids (Parsec, Android Studio), a question no flag answers (Battle.net's install folder) — the update ends as a skip that says what to do, not as an offer to force, uninstall or reinstall the package.
- **Listed twice**: winget's Visual Studio rows go when the Visual Studio provider scanned (once it had updated Visual Studio, winget's row failed and offered to reinstall it), and `self`'s GitHub CLI goes when winget lists `GitHub.cli`.

## 🧪 Tests

**8199 tests in 376 files** (0.5.0: 8032 in 366). The suites keep asserting the French interface, byte for byte — the guarantee that French did not move — and English tests cover each part. A startup guard loads the whole command line before any language is chosen and fails on any text read while modules load, the one way a label could stay English for a French user. End-to-end smoke tests run the built CLI in its default English and after `gup language fr`.

## ⬆️ Upgrade

```bash
npm i -g @charles_lindecker/gup@0.5.1 --allow-scripts=node-pty
gup --version     # 0.5.1
gup language fr   # only if you want the French interface back
```

- **The interface language changes**: 0.5.0 spoke French; 0.5.1 speaks English until you run `gup language fr` (or set `GUP_LANG=fr`). Nothing else changes: same commands, flags, settings file, schedules, history.
- **Windows**: to update gup itself, quit it first (see above) — including when an earlier attempt from inside gup failed half way.
- Scheduled updates keep running; their messages follow the language too.
