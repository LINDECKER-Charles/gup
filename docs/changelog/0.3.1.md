# 0.3.1 — 2026-08-08

[Release notes](../releases/0.3.1.md) · [GitHub Release](https://github.com/LINDECKER-Charles/gup/releases/tag/0.3.1) · [npm](https://www.npmjs.com/package/@charles_lindecker/gup/v/0.3.1) · [Compare `0.3.0...0.3.1`](https://github.com/LINDECKER-Charles/gup/compare/0.3.0...0.3.1)

**11 commits** · Charles Lindecker

gup 0.3.1 introduces a local activity history: every scan and every update attempt is appended synchronously to a monthly JSONL shard under the platform state directory, opt-out via GUP_HISTORY=0 and relocatable via GUP_HISTORY_DIR, and never read back by the tool. To make that possible, the four direct provider.update() call sites collapse into a single ui/apply-update seam. The release also turns dead code into a lint/typecheck gate (fixing the stale imports that motivated it), and reorganises the documentation into topic pages with a terminal demo rendered from a real scan.

## Added

- **core/history:** Append every scan and update attempt to a monthly JSONL shard (`<state dir>/gup/history/YYYY-MM.jsonl`) with a per-process `runId`, `success`/`failed`/`skipped` status, version delta, retry and elevated flags; `GUP_HISTORY=0` disables it, `GUP_HISTORY_DIR` relocates it, and an unwritable location warns once on stderr without failing the run ([`9bf67ca`](https://github.com/LINDECKER-Charles/gup/commit/9bf67ca))
- **ui:** Route the batch, targeted and retry update paths through a single `applyUpdate`/`applyEach` seam that dispatches, finalizes the outcome and records it to the history with per-package durations; `gup list` records its scan, and the elevated batch is logged by the parent process only ([`c6421dd`](https://github.com/LINDECKER-Charles/gup/commit/c6421dd))
