# 0.4.0 — not yet published

[Release notes](../releases/0.4.0.md) · [Compare `0.3.2...0.4.0`](https://github.com/LINDECKER-Charles/gup/compare/0.3.2...0.4.0)

**38 commits** · Charles Lindecker, dependabot[bot]

0.4.0 fixes the terminal freezes seen on Windows — provider detection no longer bursts ~140 synchronous process creations, and every probe and scan command is bounded in time with stdin closed — and turns the interactive mode into a full-screen OpenTUI app — a package table to check and filter, live scan, dialogs, mouse support — replacing `@inquirer/prompts` and `ora`. To load OpenTUI's native renderer through `node:ffi`, the runtime floor moves to Node >= 26.9.0, after an earlier move in the same range from 22.13 to 24.11; both are breaking for users on the older lines. Three security advisories are cleared (`adm-zip`, `brace-expansion`, `nanoid`), the docs are reorganised, and Dependabot moves to a weekly cadence.

## Added

- **ui:** Rebuild the interactive mode as a full-screen OpenTUI app — title bar, sidebar, bordered panels (Scan, Paquets, Providers, Options), dialogs, key-hint bar, mouse support — with a package table where one or several packages are picked by Space or click, a provider at once from its row, everything with `a`, and a `/` filter that keeps what is checked; updates leave the app to run in the real terminal and come back with a rescan, and the one-shot commands reuse the same scan view, table and dialogs on their own screens (`feat(ui): rebuild the interactive mode as a full-screen OpenTUI app`)
- **ui:** Rebuild every interactive moment on OpenTUI — the menu with its status as context, a provider-grouped package picker, confirmations, text input and a live scan screen — on the terminal's alternate screen, one renderer per interaction destroyed before anything else runs, so no prompt holds the keyboard while an installer has the terminal; each answer leaves one line in the main screen, and non-interactive output never loads the native renderer ([`0938172`](https://github.com/LINDECKER-Charles/gup/commit/0938172))

## Changed

- Require Node >= 26.9.0, the first release with `node:ffi` on by default: engines, `@types/node` on the 26 line, tsup target `node26`, CI and the security workflow on Node 26, documented minimums and landing facts updated — **breaking** for Node 24 users ([`4d2d919`](https://github.com/LINDECKER-Charles/gup/commit/4d2d919))
- Require Node >= 24.11.0 (was 22.13.0): engines, tsup target `node24`, `@types/node` on the 24 line, CI matrix reduced to Node 24, and every documented minimum updated; npm now reports EBADENGINE on Node 22 ([`4ff78a2`](https://github.com/LINDECKER-Charles/gup/commit/4ff78a2), [#66](https://github.com/LINDECKER-Charles/gup/pull/66))

## Fixed

- **ui:** Keep the Windows console from crashing when an update starts from the app: conhost 10.0.26100 (Windows 11 24H2) dies with an access violation when the alternate screen is left after stdin went back to line mode, which is OpenTUI's teardown order — gup now holds raw mode until the renderer is destroyed (`fix(ui): leave the alternate screen before raw mode to keep conhost alive`)
- **core:** Stop provider detection from freezing the terminal on Windows: PATH lookups resolve in-process instead of spawning `where` (synchronous burst 3.3–3.8 s → 9 ms, detection spawns 162 → 13), detection runs 8 probes at a time with a 15 s cap and fails soft, and `run()` closes the child's stdin, caps it at 180 s and kills the whole process tree so a prompting or wedged probe can no longer hang the scan ([`5bfd6d6`](https://github.com/LINDECKER-Charles/gup/commit/5bfd6d6))

## Removed

- **deps:** Drop `@inquirer/prompts` and `ora`, superseded by the OpenTUI interface ([`0938172`](https://github.com/LINDECKER-Charles/gup/commit/0938172))

## Security

- **deps:** Bump `adm-zip` to 0.6.1 for GHSA-8238-w5pm-2374 (unhandled error in async DEFLATE decompression crashes the process) and transitive `brace-expansion` to 5.0.12 for three DoS advisories reached through eslint's `minimatch`; `audit-ci` counts dev dependencies, so either failed the security workflow ([`6e65456`](https://github.com/LINDECKER-Charles/gup/commit/6e65456))
- **deps:** Bump transitive nanoid to 3.3.18 in both the root and `/index` lockfiles for GHSA-2v37-7h3g-55p8 (infinite loop on size 0), bringing `npm audit` back to 0 vulnerabilities and unblocking the security workflow ([`72eb6b8`](https://github.com/LINDECKER-Charles/gup/commit/72eb6b8), [`279d410`](https://github.com/LINDECKER-Charles/gup/commit/279d410), [#65](https://github.com/LINDECKER-Charles/gup/pull/65))
